# QA Fundamentals

This section presents the fundamental concepts and practices I use to structure Software Quality Assurance and Software Testing activities.

The purpose of these documents is to demonstrate my understanding of the testing lifecycle, from defining the testing approach and acceptance criteria to executing test cases and reporting defects.

---

## Contents

### Test Strategy

Defines the overall approach used to ensure software quality.

It establishes the testing objectives, scope, testing types, risk considerations, environments, tools, and general principles that guide the QA process.

**Key topics:**

- Testing objectives
- Scope and coverage
- Testing types
- Testing levels
- Risk-based testing
- Test environments
- Tools and resources
- Entry and exit criteria
- Quality objectives

---

### Test Plan

Describes how testing will be planned and executed for a specific project, feature, release, or product.

While the Test Strategy defines the overall approach, the Test Plan translates that approach into an actionable testing plan.

**Key topics:**

- Test scope
- Objectives
- In-scope and out-of-scope items
- Testing approach
- Test environment
- Resources and responsibilities
- Schedule
- Risks and dependencies
- Entry criteria
- Exit criteria
- Test deliverables

---

### Test Cases

Documents individual scenarios used to verify whether the software behaves according to its requirements and expected behavior.

Test cases are designed to be clear, reproducible, and traceable.

**Key topics:**

- Test Case ID
- Test objective
- Preconditions
- Test data
- Test steps
- Expected results
- Actual results
- Test status
- Priority
- Severity
- Positive and negative scenarios
- Boundary and edge cases

---

### Acceptance Criteria

Defines the conditions that must be satisfied for a feature, requirement, or user story to be considered complete and acceptable.

Acceptance criteria establish a shared understanding between business stakeholders, developers, and QA.

**Key topics:**

- Functional expectations
- Business rules
- User behavior
- Positive scenarios
- Negative scenarios
- Validation conditions
- Definition of Done support
- Testability of requirements

---

### Bug Reports

Describes how software defects are documented, communicated, and tracked.

A good bug report should provide enough information for the development team to understand, reproduce, investigate, and resolve the issue.

**Key topics:**

- Bug ID
- Summary
- Environment
- Preconditions
- Steps to reproduce
- Expected result
- Actual result
- Severity
- Priority
- Reproducibility
- Evidence
- Additional technical information

---

### Test Execution

Documents the execution of test cases and the results obtained during a testing cycle.

It provides visibility into the current quality status of the software and helps identify failed, blocked, or successful scenarios.

**Key topics:**

- Test execution cycles
- Pass / Fail / Blocked status
- Test evidence
- Defect association
- Retesting
- Regression testing
- Execution metrics
- Test coverage
- Test results
- Release readiness

---
